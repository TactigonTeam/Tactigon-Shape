# Security Policy

The Tactigon SHAPE team takes the security of the project seriously. We appreciate the efforts of security researchers and users who responsibly disclose vulnerabilities and help us keep the project secure.

## Supported Versions

Security updates are provided for the latest supported development branch.

| Version | Supported |
| ------- | --------- |
| `master` | :white_check_mark: |
| Previous versions | :x: |

Security fixes are applied to the latest supported codebase. Users are encouraged to keep their installations up to date.

Support for specific releases, when available, will be explicitly documented.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues or Pull Requests.**

If you discover a potential security vulnerability in Tactigon SHAPE, please report it privately so that the maintainers can investigate and address it before the issue becomes public.

### How to Report

Use GitHub's **Private Vulnerability Reporting** feature:

https://github.com/TactigonTeam/Tactigon-Shape/security/advisories/new

When submitting a report, please include:

- A clear description of the vulnerability.
- The affected component, file or module.
- The affected version or commit, if known.
- Steps to reproduce the issue.
- Potential security impact.
- Proof-of-concept code or screenshots, if available.
- Any suggested mitigation or remediation.

Please provide enough information to help us reproduce and assess the vulnerability.

### Response and Disclosure Process

We aim to follow this process for every vulnerability report:

1. **Acknowledgement:** We aim to acknowledge receipt of a report within 5 business days.
2. **Assessment:** The maintainers will investigate the report, assess its severity and determine which versions or components are affected.
3. **Updates:** We aim to provide progress updates at least every 10 business days while the investigation is ongoing.
4. **Resolution:** If the vulnerability is confirmed, we will work on a fix and prepare a security update.
5. **Disclosure:** Once a fix is available, we may publish a GitHub Security Advisory describing the vulnerability, its impact and the affected versions.

These response times are targets rather than guaranteed deadlines.

### What to Expect

- **If the vulnerability is accepted:** The maintainers will work on a remediation and coordinate a responsible disclosure.
- **If the vulnerability is declined:** The reporter will receive an explanation of the assessment and the reasons why the issue was not considered a security vulnerability.
- **If more information is required:** The maintainers may request additional details to reproduce or assess the reported behavior.

### Responsible Disclosure

We ask security researchers to:

- Give maintainers reasonable time to investigate and fix reported vulnerabilities before public disclosure.
- Avoid publicly sharing exploit details before a fix is available.
- Avoid accessing, modifying or deleting data belonging to other users.
- Avoid disrupting services or impacting other users during security testing.
- Perform security research only on systems they are authorized to test.

We appreciate responsible disclosure and will acknowledge the contributions of security researchers when appropriate and with their consent.

## Thank You

Thank you for helping us keep Tactigon SHAPE and its community secure.

The Tactigon SHAPE maintainers appreciate your cooperation and responsible security research.
